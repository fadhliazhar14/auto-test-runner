Dokumentasi Codebase: Auto Test Runner

1. Gambaran Umum Proyek

Auto Test Runner adalah sebuah aplikasi desktop berbasis Java yang dirancang untuk mengelola dan mengeksekusi skenario pengujian otomatis berdasarkan metodologi Behavior-Driven Development (BDD). Aplikasi ini memungkinkan pengguna (seperti QA Engineer atau developer) untuk menulis, menyimpan, dan menjalankan skenario tes dalam format Gherkin (Given-When-Then) melalui antarmuka grafis (GUI) yang intuitif.

Tujuan utama dari aplikasi ini adalah untuk menyederhanakan proses BDD testing dengan menyediakan alat terpusat yang mengintegrasikan penulisan skenario, eksekusi melalui Selenium, dan penyimpanan hasil ke database.

2. Teknologi yang Digunakan

Aplikasi ini dibangun menggunakan beberapa teknologi dan library utama:

Bahasa & Platform

  • Java 17: Versi modern dari Java yang menjadi dasar aplikasi.
  • Java Swing: Framework untuk membangun antarmuka aplikasi desktop.

Testing & Automasi

  • Cucumber 7.15.0: Framework untuk implementasi BDD.
  • Selenium 4.15.0: Alat untuk automasi interaksi browser (web testing).
  • WebDriverManager: Mengelola driver untuk Selenium secara otomatis.
  • JUnit 5: Framework untuk unit testing.

Database

  • MySQL 8.0: Sistem database relasional untuk menyimpan data skenario dan hasil tes.
  • HikariCP: Library connection pool untuk manajemen koneksi database yang efisien.

Build & Lainnya

  • Maven: Alat untuk manajemen dependensi dan build proyek.
  • Logback & SLF4J: Framework untuk logging aktivitas aplikasi.
  • Jackson: Library untuk pemrosesan data JSON.

3. Arsitektur Aplikasi

Aplikasi ini mengadopsi arsitektur berlapis (Layered Architecture) untuk memisahkan tanggung jawab dan meningkatkan maintainability. Berikut adalah lapisan-lapisan utamanya:

  1. Presentation Layer (UI): Dibangun menggunakan Java Swing, lapisan ini bertanggung jawab untuk menampilkan data kepada pengguna dan menangkap input. Terletak di dalam package com.fadhli.automation.ui.
  2. Service Layer (Business Logic): Lapisan ini berisi logika bisnis utama aplikasi, seperti validasi data dan koordinasi antar komponen. Terletak di package com.fadhli.automation.service.
  3. Data Access Layer (DAO): Bertanggung jawab untuk abstraksi operasi database (CRUD). Menggunakan DAO Pattern untuk memisahkan logika bisnis dari logika akses data. Terletak di package com.fadhli.automation.dao.
  4. Database Layer: Merupakan database MySQL yang menyimpan semua data persisten.

Alur data umumnya adalah: UI -> Service -> DAO -> Database, dan sebaliknya.

4. Struktur Database

Aplikasi menggunakan database MySQL untuk menyimpan data. Skema tabel utama dibuat secara otomatis saat aplikasi pertama kali dijalankan.

Tabel `scenario`

Menyimpan informasi utama tentang sebuah skenario tes.

CREATE TABLE scenario (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    feature_name VARCHAR(255) NOT NULL,
    scenario_name VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

Tabel `step`

Menyimpan langkah-langkah (steps) yang terkait dengan sebuah skenario.

CREATE TABLE step (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    scenario_id BIGINT NOT NULL,
    step_type VARCHAR(10) NOT NULL, -- "Given", "When", "Then", "And"
    step_text TEXT NOT NULL,
    step_order INT NOT NULL,
    FOREIGN KEY (scenario_id) REFERENCES scenario(id) ON DELETE CASCADE
);

5. Fungsionalitas Utama

Berikut adalah fungsionalitas inti yang disediakan oleh aplikasi:

Manajemen Skenario

Pengguna dapat melakukan operasi CRUD (Create, Read, Update, Delete) untuk skenario tes, termasuk menambahkan dan mengedit langkah-langkah tes secara dinamis.

Eksekusi Tes

Menjalankan skenario tes yang dipilih menggunakan engine Cucumber. Selenium akan membuka browser dan menjalankan interaksi sesuai dengan step definitions yang ada.

Logging & Monitoring

Aplikasi menampilkan log eksekusi secara real-time di sebuah console. Jika terjadi kegagalan, aplikasi juga akan otomatis mengambil screenshot halaman web pada saat itu.

Penyimpanan Persisten

Semua skenario dan langkah-langkahnya disimpan di dalam database MySQL, sehingga data tidak hilang saat aplikasi ditutup dan dapat diakses kembali.

6. Panduan Setup dan Menjalankan Aplikasi

Berikut langkah-langkah untuk menyiapkan dan menjalankan proyek di lingkungan lokal.

Prasyarat

  • Java 17 (atau lebih tinggi)
  • Maven 3.6 (atau lebih tinggi)
  • MySQL 8.0 (atau lebih tinggi)
  • Google Chrome (terinstal)

Langkah-langkah

  1. Konfigurasi Database:

    Edit file src/main/resources/database.properties dan sesuaikan dengan konfigurasi MySQL Anda, terutama username dan password.

    db.url=jdbc:mysql://localhost:3306/bdd_test_runner?createDatabaseIfNotExist=true
db.username=root
db.password=password_anda
  2. Build Proyek:

    Buka terminal di direktori root proyek dan jalankan perintah Maven untuk mengkompilasi kode dan mengunduh dependensi.

    mvn clean compile
  3. Menjalankan Aplikasi:

    Setelah build berhasil, jalankan aplikasi menggunakan perintah Maven berikut:

    mvn exec:java -Dexec.mainClass="com.fadhli.automation.BddTestRunnerApplication"

    Alternatif lain adalah dengan membuat file JAR yang bisa dieksekusi:

    mvn clean package
java -jar target/bdd-test-runner-1.0.0.jar

Saat pertama kali berjalan, aplikasi akan secara otomatis membuat database dan tabel yang diperlukan jika belum ada.
